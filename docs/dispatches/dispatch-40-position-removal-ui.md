# Dispatch 40 — explicit position removal and strict save recovery

October 23, 2026 Pacific. Source implementation and isolated acceptance only; not deployed or enabled. Builds on merged PRs #59–62. Last verified production remains PR #53 `62acacb`; no managed secret/IAM, real staffing, account, provider or consumer credential change was performed.

## User workflow

The existing Person editor offers Company-wide System Administrators a **Review replacement or vacancy** action when a selected position is removed while it still owns assignments. Routine position additions remain ordinary reviewed Person edits; adding DM does not automatically assign a District or vacate a store. Inactivation/account unlinking remains a separate guarded workflow.

The short review loads a fresh complete Directory after checking capability/recovery. A changed Person version or original position set blocks the old draft. Each affected assignment requires an explicit eligible replacement or explicit vacancy; nothing is preselected. Retained positions/assignments remain visible and unchanged. District DM ownership is one decision with its inherited active/retired store count, not independent store overrides. New replacements require explicit controlled positions, Active lifecycle and eligible current hierarchy; retired/unresolved owners offer vacancy rather than a new assignment. Existing members cannot be duplicated in multi-member slots.

Workplace/support links, contacts, IDs, store hierarchy and accounts are retained. Mixed profile edits are kept and must be saved/discarded separately rather than silently included or lost. Required current Pending request acknowledgments remain explicit and do not approve or rewrite those requests. Reason is bounded to 1,000 characters. The fresh signed server review is still the authority for plan readiness; the browser's choices are not permission to write.

After server review, **Confirm and save** performs durable preparation and then the one staffing commit under the same frozen command/UUID. A failed or unknown preparation stops before commit, with no automatic retry. Choice edits invalidate the old review. The existing modal footer keeps controls visible on mobile; heading/status focus and the existing keyboard trap are retained. Escape/backdrop/close cannot dismiss an unresolved or active operation. A lost reply preserves its marker and offers status or explicit cancellation, never an automatic new submission. Profile **Recover interrupted staffing change** supports reload recovery without reconstructing a command.

## Integration repairs

`refreshTransitionDirectory` is deliberately separate from best-effort operating polling. It rejects concurrent/skipped refresh, pending or intervening writes, incomplete/duplicate/invalid saved data and stale actor/generation. No marker is cleared until complete current saved state has been validated and applied. The protected bootstrap read shares the bounded authenticated transport deadline and session fences. Required response collections are complete, not silently defaulted; a conservative 50,000-row-per-collection validation cap fails closed, never truncates. This does not make the existing multi-collection bootstrap an atomic inventory; the actual writer still rereads coherent transactional dependencies.

Real browser testing found and repaired native `fetch` receiver binding, which synthetic functions did not expose. Reload acceptance also found the old Directory mount cleanup deleted every `shiekh_` key, including recovery markers. Legacy record caches are still purged, but the minimal actor-namespaced recovery prefix is preserved. Corrupt/unknown markers are not guessed away; explicit sign-out still clears protected local data. This is application-level isolation, not encryption or an XSS security boundary.
