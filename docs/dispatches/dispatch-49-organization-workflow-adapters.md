October 28, 2026 Pacific. Continues [the roster/onboarding plan](../plans/organization-leadership-roster.md), based on PR #78 head `52d92355166363213385ab04a576509bdeebceb1`. This phase adds private server adapters and a shared typed contract; it does not change public API v1/v2/v3, consumers, credentials, IAM or production configuration.

## Server boundary

`/api/directory/organization-leadership` supplies administrator-only `GET capabilities`, `GET catalog`, `GET operations`, and `POST prepare/commit/status/cancel`. Existing Firebase authentication resolves the actor; fresh Company-wide Active administrator authority is still rechecked in each database transaction. No browser-supplied actor, patches or completeness assertion is trusted. Unknown infrastructure errors stay private, responses are no-store/no-ETag, and JSON is bounded to 32 KiB before the generic commit parser. Existing parent limits and separate actor read/command limits apply. No automatic retry or alternate generic-write fallback exists.

`organizationLeadershipConfiguration.ts` introduces three **server-only flags, all off by default**: `ORGANIZATION_LEADERSHIP_CATALOG_ENABLED`, `ORGANIZATION_LEADERSHIP_RECOVERY_ENABLED`, `ORGANIZATION_LEADERSHIP_COMMANDS_ENABLED`. New commands require all three exact `true` values and complete Store support. Recovery remains independent of command/catalog admission. Store methods enforce admission again. Older Person/signing flags and consumer API grants do not enable this workflow. None of these environment values was set in production.

The catalog reads complete bounded unit/Person/assignment/Location projections in one read-only transaction. It returns stable namespaced IDs, versions, Primary/Additional membership, candidate eligibility, retail counts and readable diagnostics. Contacts, workplace, accounts and raw planning preconditions are excluded. Missing/ineligible People stay visibly unresolved, not vacancies; eligible discovery is separate from actual membership. Non-retail Locations never supply management scope. Source and final projected responses are bounded to 8,000,000 estimated/serialized bytes; counts are at most 500 Districts, 100 Regions, 5,000 People, 15,000 tenures and 1,000 Locations. Unsupported/inconsistent business data is diagnosed; failed/incomplete source is rejected.

The actor-only pending-review list projects metadata, includes expired prepared reviews for explicit cancellation and caps at 100. Fresh preparation reads/writes a private `organization_leadership_admission` actor record, serializing competing admissions so the complete recovery list cannot be exceeded by concurrent new preparations. Admission/receipt changes are atomic; neither collection is generically writable or client-accessible. No mail/sign-in/account grants are created. Terminal operation replay remains available at capacity.
